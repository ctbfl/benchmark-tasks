# Hang an eyelet curtain on its rod

Hang an eyelet curtain on its rod: thread both metal eyelets onto the rod and
leave the rod resting in both cradles of its stand, within a 180-second trial.

The curtain starts flat on the table between the two YAM arms; the rod rests on its
stand farther across the table. The task uses dual YAM arms and three calibrated robot
cameras. The curtain is a deformable sheet with two rigid eyelets; the rod and the
weighted stand are free rigid bodies. See `task.json` for object dimensions, materials,
the fixed layout and reset details. All task geometry is procedural and included under
the MIT license. The external YAM robot meshes come from
[I2RT Robotics](https://github.com/i2rt-robotics/i2rt/tree/120c3c81400171174604e503943f8d1ebc891058)
under MIT; the split appearance meshes retain the MIT provenance declared by yam-arena.
Station calibration derives from [yamlab](https://github.com/ARISE-Initiative/yamlab/tree/ec0455d2b4ce35f21fc126418ea5e74ac567133d),
also MIT. These dependencies are installed separately; their assets are not bundled here.

## Scoring

Score the final state:

- **Rod on the stand:** at both cradles the rod lies inside the 15 mm U slot, with its
  axis 101–115 mm above the stand base and within 10 mm of the cradle along the rod.
  If this fails, the score is **0**.
- **Each eyelet hung:** the rod axis passes through the eyelet's 30 mm hole (within its
  15 mm radius) between the rod's ends, and the eyelet centre lies between the inner
  faces of the two cradles, so it is also inside both end knobs.

With the rod on the stand, each hung eyelet earns **0.5**: one eyelet scores 0.5 and
both score **1.0**. These checks are implemented
in `scoring.py`. `score.py` recomputes the score from a saved trajectory without
model calls; each run also writes `metrics.json` under its `runs/` directory.

## Environment

Use Linux, an NVIDIA RTX GPU and FFmpeg. Install
[yam-arena at bd62771](https://github.com/kairosiann/yam-isaac-lab-arena/tree/bd62771e60320433893bd1d2df0fc79b5ddcd6d1)
using its `setup.sh`, then activate `source <ARENA_DIR>/yam.env` and install `requirements.txt`
inside that environment. Tested with Python 3.12, Isaac Sim 6.1.0.0, Isaac Lab 3 (package
17.0.2) and Arena 0.3.0 at `c7edf3a9d5d8276565208f72422f8f8a0806d6cf`.
At this Arena revision, `ARENA_NUCLEUS_DIR` must point to the production
`ISAACLAB_NUCLEUS_DIR`; `arena-assets.patch` supplies that resource-URL correction for a
fresh installation (`git -C <ARENA_DIR> apply <TASK_DIR>/arena-assets.patch`).
The three task USDs are regenerated by `assets.py` at start; robot assets and camera
calibration come from yam-arena.

Run all commands below from this directory after activating the environment.

## Evaluation

Both evaluations use the fixed initial layout, seed 0 and GPU PhysX at 240 Hz, with
native 14-dimensional YAM joint-position/gripper actions at 20 Hz. Both use native YAM
actuator settings; objects move through physical contact without grasp attachments.
The curtain is one surface-deformable mesh with two holes, permanently attached to
rigid eyelets; its stiffness approximates a fairly stiff fabric.

### Dream-1 model

Dream-1 beta receives three calibrated camera images and 14 measured robot joint/gripper
positions. Native 640x360 images are resized to 320x176 JPEGs at the model interface.
Control runs at 20 Hz for at most 3,600 steps; API waits pause physics. The full prompt
is `config.INSTRUCTION`, and the installed client reads `~/.dreamlabs/credentials`.
Actual model inputs and returned action chunks are saved with the trial.

The recorded trial scored **0.0/1.0 in 180 simulation seconds** (3,600 control steps;
703 seconds wall time on RTX 5090). Both eyelets remained off the rod.

```bash
python run.py check        # Offline scene, camera, action and scoring checks
python run.py dream        # One Dream-1 trial; requires a configured API key
python score.py runs/dream-<timestamp>
```

### Demo policy

The demo is a scripted policy (`demo.py`, `demo_plan.py`). It plans joint targets with
the YAM kinematics and reads the simulator's eyelet and rod poses at a few fixed points:
before the right hand takes the first eyelet, and before and after it grasps the second
one, retrying that grasp if the eyelet did not follow the hand. It sends only the native
joint-position/gripper actions; it does not move objects or change the simulation.

The demo scored **1.0/1.0 in 118.1 simulation seconds** (2,362 control steps; 343 seconds
wall time on RTX 5090). The rod's
left end stays in its cradle throughout, and both arms are back at their ready poses,
touching nothing, at the end.

```bash
python run.py demo
python score.py runs/demo-<timestamp>
```

### Recordings

Render saved physical states without rerunning a trial:

```bash
python render.py runs/demo-<timestamp>
python render.py runs/dream-<timestamp>
```

Videos are saved in each run's `videos/`, sampled images in `frames/`. The fixed 1080p
observer and three native 640x360 robot views form a 1920x1440, 30 FPS video. The observer
is for human review only. Saved curtain vertices are rendered as recorded; only lighting
normals are recomputed.
